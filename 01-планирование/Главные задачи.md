# Главные задачи

1. Узнать основные требования к документации:
   - язык документации;
   - формат передачи;
   - ограничения по объёму;
   - требования к иллюстрациям;
   - возможность использовать Git как рабочие записки.

2. Определить целевую аудиторию:
   - человек, который никогда не играл в Тетрис;
   - человек, который может не иметь опыта в видеоиграх и использовании геймпада.

3. Подготовить структуру документации:
   - объяснить основные правила игры;
   - объяснить игровое поле и фигуры;
   - показать управление;
   - провести пользователя через первую партию;
   - объяснить основные ошибки и конец игры.

4. Настроить проверку документации:
   - использовать отдельного критика для поиска логических и грамматических ошибок;
   - проверить, сможет ли неподготовленный читатель понять инструкцию;
   - отделять реальные ошибки от сведений, которых нет возможности подтвердить.

5. Проверить документацию на реальном читателе:
   - дать материал человеку без опыта в Тетрисе;
   - собрать вопросы и непонятные места;
   - внести изменения по результатам проверки.

6. Зафиксировать процесс работы:
   - сохранять рабочие решения и изменения;
   - фиксировать причины важных решений;
   - хранить результаты проверок;
   - не включать буферные материалы в рабочую структуру.

7. Подготовить финальную документацию для передачи через Google Docs.
