# Стек

## Текущий стек

- **GPT-5.6 Luna** — основная модель для подготовки, редактирования и анализа документации.
- **Antigravity** — среда для выполнения верстки документа по инструкции; используется для оформления Google Docs и вставки визуальных материалов.
- **Google Docs MCP** — программный доступ к Google Docs для чтения структуры и внесения правок верстки; авторизация выполняется через OAuth.
- **OpenScreen** — запись геймплея для фиксации игровых сценариев, проверки последовательности действий и подготовки наглядных материалов.
- **BrowserSkill** — браузерная валидация документации и её оформления в Google Docs, включая проверку структуры, отображения текста, изображений и GIF.
- **Google Docs** — передача финальной версии документации.
- **Git** — хранение рабочих записок, решений, результатов проверок и истории изменений.
- **Obsidian** — ведение локальных заметок и связей между материалами.

## Изменение подхода

Изначально для работы рассматривался Gemini. От этого варианта я отказался и перешёл на GPT-5.6 Luna как основную модель для подготовки документации.

OpenScreen добавлен в стек для записи геймплея. Записи используются как дополнительный материал для проверки инструкций и подготовки визуальных примеров.

BrowserSkill добавлен в стек для проверки документации в реальном браузере. С его помощью можно проверять структуру Google Docs, расположение заголовков, переносы страниц, выравнивание изображений и доступность документа по ссылке.

Antigravity и Google Docs MCP добавлены в стек для формирования верстки. Antigravity выполняет операции оформления по инструкции, Google Docs MCP обеспечивает программный доступ к документу.

## Назначение инструментов

1. Сначала формулируются требования и цели документации.
2. Затем создаётся и редактируется текст документации.
3. С помощью OpenScreen фиксируется реальный игровой процесс.
4. Верстка документа выполняется через Antigravity и Google Docs MCP.
5. С помощью BrowserSkill проверяется отображение документации в браузере и Google Docs.
6. Материалы проверяются на понятность и последовательность.
7. В Git сохраняются рабочие решения и результаты этих проверок.
