# Инструкция по верстке документа для Antigravity

## Задача

Привести документ `Tetris tech-docs` к единому и аккуратному виду в Google Docs.

Главная цель верстки — сделать документ понятным для человека, который впервые знакомится с Тетрисом. Текст, изображения и подписи должны восприниматься как единая последовательность действий.

Содержание текста не переписывать без отдельного указания. Не менять смысл, порядок объяснения и стиль повествования. Во время этой работы нужно заниматься только оформлением, размещением изображений и техническими переносами.

2. `Запуск игры и первые действия`

```text

```

Её английский заголовок:

```text
Starting the Game and Taking Your First Steps
```

## Главное правило работы

Работать только с одним блоком за один проход.

Сначала полностью оформить и проверить блок `Rotating a Piece`. После этого остановиться и сохранить результат. Остальные блоки не менять, пока первый блок не утверждён.

Если точное место вставки не найдено, не вставлять изображение. Сначала найти нужный текст через поиск Google Docs или визуально проверить положение курсора.

Не добавлять разрывы страниц вслепую. Перед вставкой page break убедиться, что курсор находится в нужном абзаце.

## Единая иерархия заголовков

Использовать встроенные стили Google Docs, а не форматировать заголовки вручную.

### Стиль Title

Использовать только для названия главы:

```text
Starting the Game and Taking Your First Steps
```

### Стиль Heading 2

Использовать для основных разделов:

```text
Starting the Game
Checking the Controls
Practical Examples
```

### Стиль Heading 3

Использовать для отдельных практических примеров:

```text
Rotating a Piece
Moving a Piece
Making a Piece Fall Faster
Completing a Horizontal Line
Ending the Game
```

### Основной текст

Обычный текст использовать для инструкций, пояснений и ожидаемых результатов.

Не создавать заголовки вручную увеличением размера шрифта. Это нарушает структуру документа и мешает автоматическому оглавлению.

## Общий шаблон практического блока

Каждый блок оформлять в одинаковом порядке:

```text
Heading 3: Action title

Short explanation of the action.

Image sequence with numbered captions.

Expected result.
```

Пример:

```text
Rotating a Piece

Use the rotate control to turn the piece 90 degrees. On a keyboard, this may be the Up Arrow.

1. Before rotation
[image]

2. Press the rotate control
[image]

3. After rotation
[image]

The piece changes its position on the playfield.
```

Не оставлять заголовок внизу страницы, если относящееся к нему изображение переносится на следующую страницу. Заголовок, описание и первый визуальный пример должны находиться рядом.

## Работа с изображениями из Google Drive

Материалы находятся в аккаунте `georgegoncharov101@gmail.com` в папке:

```text
tetris-doc/source-pic
```

Использовать следующие материалы:

```text
pressUP/              — Rotating a Piece

```

Кадры внутри папок вставлять в исходном порядке по номерам файлов.

Для поворота использовать:

```text
press_Up1-0.png
press_Up2-0.png
press_Up3-0.png
press_Up4-0.png
```

Для окончания игры использовать:

```text
end_game1-0.png
end_game2-0.png
end_game3-0.png
```

## Вставка изображения

1. Установить курсор в нужное место после объясняющего текста.
2. Выбрать `Insert → Image → Drive`.
3. Открыть папку `tetris-doc/source-pic`.
4. Открыть нужную подпапку.
5. Выбрать файл по имени.
6. Вставить изображение.
7. Установить режим изображения `In line` или `In text`.
8. Выровнять изображение по центру.
9. Задать одинаковый размер для всех кадров одного блока.
10. Проверить, что подпись находится непосредственно рядом с изображением.

Для практических кадров не использовать плавающий режим `Wrap text` или `Break text`, если он приводит к смещению изображений. Режим `In line` наиболее стабилен для последовательности.

## Унифицированная обрезка

Все кадры одного практического примера должны иметь:

- одинаковую область обрезки;
- одинаковое соотношение сторон;
- одинаковый масштаб игрового поля;
- одинаковое положение игрового поля на изображении;
- одинаковую ширину в Google Docs.

Не обрезать каждый кадр по текущему положению фигуры. Иначе игровое поле будет смещаться, и читателю будет трудно сравнивать кадры.

Для отдельного действия оставлять:

- игровое поле;
- текущую фигуру;
- нужную область управления, если она важна для примера.

Убирать:

- декоративный фон;
- несвязанные панели интерфейса;
- случайные курсоры и артефакты;
- лишнее пустое пространство;
- элементы `HOLD`, `SCORE`, `LEVEL`, `LINES` в примерах, где они не объясняются.

Полный интерфейс оставлять только в блоке, где объясняется общий экран игры.

## Размер изображений

Исходный размер подготовленного изображения может быть:

```text
15.91 cm × 11.91 cm
```

Не растягивать изображения отдельно по ширине и высоте. Сохранять пропорции.

Если два кадра размещаются в одной строке, использовать одинаковую ширину для обоих. Примерный размер для двух изображений:

```text
7.5 cm × 5.62 cm
```

Если изображение становится слишком маленьким для чтения, размещать кадры вертикально, по одному на строке.

Для Google Docs предпочтительнее крупные изображения по одному, чем мелкая сетка из четырёх нечитаемых кадров.

## Подписи к кадрам

Использовать короткие подписи на английском языке:

```text
1. Before rotation
2. Press the rotate control
3. After rotation
```

Подписи должны:

- иметь одинаковый стиль;
- быть выровнены одинаково;
- находиться непосредственно над или под соответствующим кадром;
- описывать действие и результат;
- не содержать длинных объяснений.

Не использовать случайные пробелы для выравнивания подписей. Если нужно разместить кадры в ряд, использовать таблицу без видимых границ.

## Размещение кадров в ряд

Для двух или трёх кадров использовать таблицу:

```text
Insert → Table → 2 × 1
```

или:

```text
Insert → Table → 3 × 1
```

В каждую ячейку поместить:

```text
номер и короткая подпись
изображение
```

После вставки:

1. Выделить таблицу.
2. Открыть свойства таблицы.
3. Установить цвет границы прозрачным или ширину `0 pt`.
4. Выровнять содержимое ячеек по центру.
5. Установить одинаковые внутренние отступы.

Если кадры становятся слишком маленькими, удалить таблицу и разместить изображения вертикально.

## Правила переноса страниц

- Не оставлять заголовок внизу страницы без текста.
- Не оставлять подпись отдельно от изображения.
- Не переносить первый кадр практического блока на отдельную страницу без его заголовка.
- Не добавлять несколько пустых строк для управления переносом.
- Не использовать много ручных горизонтальных линий.
- Для нового крупного раздела использовать один осмысленный page break, если он действительно нужен.

Если блок не помещается целиком:

1. Сначала попробовать уменьшить вертикальные отступы.
2. Затем уменьшить изображения, сохранив читаемость.
3. Если это не помогает, перенести весь блок на следующую страницу.

## Оформление первого эталонного блока

Оформить сначала только `Rotating a Piece`.

Структура:

```text
Rotating a Piece

Use the rotate control to turn the piece 90 degrees. On a keyboard, this may be the Up Arrow.

1. Before rotation
[press_Up1-0.png]

2. Press the rotate control
[press_Up2-0.png]

3. After rotation
[press_Up3-0.png or press_Up4-0.png]

The piece changes its position on the playfield.
```

Если четыре кадра важны для понимания движения, использовать все четыре. Если промежуточные кадры не добавляют информации, оставить только три ключевых состояния.

После оформления проверить:

- заголовок находится рядом с текстом;
- первый кадр не оторван от описания;
- кадры читаются в правильном порядке;
- все кадры одинакового размера;
- нет лишнего интерфейса;
- изображение не выходит за пределы рабочей области;
- следующий текст не накладывается на изображение.

## Финальная проверка

После каждого блока проверить документ в режиме просмотра:

1. Заголовок виден и соответствует уровню раздела.
2. Текст не разорван случайным переносом.
3. Изображение относится именно к предыдущему тексту.
4. Кадры идут в правильном порядке.
5. Все изображения имеют одинаковый размер внутри блока.
6. Подписи читаются и выровнены одинаково.
7. Нет больших пустых участков.
8. Нет случайных горизонтальных линий.
9. Нет смещённых, наложенных или обрезанных изображений.
10. Документ одинаково читается в режиме редактирования и просмотра.

После завершения верстки проверить документ через BrowserSkill:

- открыть ссылку в браузере;
- проверить вкладку `Chapters`;
- открыть практическую главу;
- просмотреть каждый блок сверху вниз;
- проверить переносы страниц;
- сделать скриншот каждой проблемной страницы;
- исправить только подтверждённые проблемы.

## Правило отката

Если новый блок выглядит хуже, чем исходный:

1. Немедленно отменить последнюю операцию через `Ctrl+Z`.
2. Проверить, что документ вернулся к предыдущему состоянию.
3. Не продолжать верстку до восстановления корректного положения курсора.

Не удалять весь раздел и не заменять его новым текстом без отдельного подтверждения.
