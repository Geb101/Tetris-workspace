# Анализ Google Docs

## Документ

`Tetris tech-docs`

## Дата проверки

22.09.2026

## Инструмент проверки

BrowserSkill (`bsk 0.3.0`) через подключённый браузерный профиль.

## Обнаруженная структура

Вкладка `Chapters` содержит четыре раздела:

1. `Introduction to the Game`
2. `Запуск игры и первые действия`
3. `Проверка себя`
4. `Ссылки для проверки и версии игры`

## Что уже работает

- Документ разделён на главы через вкладки.
- Практическая глава имеет понятный заголовок `Starting the Game and Taking Your First Steps`.
- Внутри главы выделены разделы `Starting the Game`, `Checking the Controls` и `Practical Examples`.
- Текст и заголовки выровнены по одной рабочей области страницы.
- Практический блок начинается с действия и ожидаемого результата.
- Изображение добавлено отдельно и визуально связано с демонстрацией игрового процесса.

## Основные проблемы

### 1. Слишком большой разрыв перед первым изображением

Текст `Rotating a Piece` и описание действия находятся внизу первой страницы, а изображение начинается на следующей странице. Между текстом и изображением возникает большой пустой участок.

Это разрывает связь между инструкцией и её визуальным примером. Читатель может не сразу понять, что изображение относится к тексту на предыдущей странице.

**Приоритет:** высокий.

**Решение:** переместить заголовок, краткое описание и первый кадр на одну страницу. Если изображение не помещается полностью, перенести весь блок целиком на следующую страницу.

### 2. Изображение показывает слишком много интерфейса

В текущем кадре одновременно видны `HOLD`, `NEXT`, `SCORE`, `LEVEL`, `LINES`, игровое поле, декоративный фон и кнопка паузы. Для примера поворота это перегружает изображение.

**Приоритет:** высокий.

**Решение:** для конкретного действия использовать отдельный crop игрового поля с текущей фигурой. Боковые панели оставить только в разделе, где объясняется общий игровой экран.

### 3. Не выделено главное изменение

На изображении не выделены отдельно:

- фигура до поворота;
- команда поворота;
- фигура после поворота.

**Приоритет:** высокий.

**Решение:** использовать последовательность `Before → Action → After` или пронумерованные кадры `1`, `2`, `3`.

### 4. Нет визуальной последовательности

Если в блоке будет несколько изображений, их нужно связать номерами или стрелками. Простая сетка изображений без нумерации выглядит как набор скриншотов.

**Приоритет:** средний.

**Решение:** использовать одинаковые кадры с подписями:

```text
1. Before rotation
2. Press the rotate control
3. After rotation
```

### 5. Не унифицированы блоки практических примеров

Для всех действий нужен один шаблон:

```text
Action title
Short instruction
Expected result
Image sequence
```

Каждый блок должен иметь одинаковые:

- стиль заголовка;
- размер основного текста;
- отступы;
- ширину изображений;
- подписи к кадрам;
- расстояние между текстом и изображением.

### 6. Слишком крупный основной заголовок

Заголовок `Starting the Game and Taking Your First Steps` визуально заметен, но занимает значительную высоту страницы. Для Google Docs лучше использовать встроенный стиль `Title` или `Heading 1`, а не ручной размер шрифта.

**Решение:** задать единый стиль заголовков для всех глав и не изменять размер вручную в отдельных местах.

### 7. Линии-разделители используются слишком часто

Горизонтальные линии между крупными блоками создают визуальные разрывы, но не заменяют иерархию заголовков.

**Решение:** оставить линию только под названием главы или убрать линии полностью и использовать встроенные стили `Heading 1`, `Heading 2` и `Heading 3`.

## Рекомендуемый макет практического блока

```text
### Rotating a Piece

Use the rotate control to turn the piece 90 degrees.
On a keyboard, this may be the Up Arrow.

1. Before rotation       2. After rotation
   [cropped image]          [cropped image]

The piece changes its position on the playfield.
```

Если изображение плохо читается в два столбца, использовать вертикальный вариант:

```text
### Rotating a Piece

Instruction.

1. Before rotation
[large cropped image]

2. After rotation
[large cropped image]

Expected result.
```

## Рекомендуемые правила для изображений

- Для общего игрового экрана оставить полный интерфейс.
- Для отдельного действия обрезать кадр до игрового поля и текущей фигуры.
- Все кадры одного примера обрезать одной областью.
- Не обрезать каждый кадр по положению фигуры.
- Использовать одинаковое соотношение сторон.
- Не растягивать изображения отдельно по ширине и высоте.
- Для практических примеров использовать PNG.
- Добавлять короткие подписи, а не длинные пояснения поверх изображения.

## Порядок исправлений

1. Убрать разрыв между текстом `Rotating a Piece` и его изображением.
2. Обрезать кадры для отдельного действия.
3. Сделать последовательность `Before → Action → After`.
4. Унифицировать размеры и подписи кадров.
5. Применить одинаковые стили заголовков ко всем главам.
6. Проверить, что каждый визуальный пример находится рядом с объясняющим его текстом.
7. Просмотреть документ в режиме предварительного просмотра или экспорта в PDF.

## Ограничение анализа
